# Релиз 1.2.0 — что отправлять в App Store и Google Play

Версия 1.2.0 приводит приложение к одному виду с сайтом my-test.kz: тот же дашборд, статистика, разбор ошибок, единый профиль и сообщество (лента, люди, чаты, группы, голосовые). Ниже — порядок действий и тексты для консолей. Биллинг и товары описаны в `STORE_RELEASE.md`.

## 0. Что должно быть на сервере ДО отправки

Приложение 1.2.0 вызывает эндпоинты, которых нет в старом API. Если отправить билд раньше деплоя, чат/жалобы вернут 404.

- [ ] Задеплоена ветка с миграцией `20260929120000_chat_message_reports` (`npm run migrate:deploy:safe` в `apps/api`).
- [ ] Задеплоены веб (модерация, жалобы на сообщения в чате) и админка (вкладка «Жалобы на сообщения»).
- [ ] В админке открывается «Модерация соцсети» и в ней есть обе очереди: жалобы на посты и на сообщения. Кто-то из команды реально отвечает на жалобы — это условие Apple 1.2 (ответ в течение 24 часов).
- [ ] На прод-сервере в `.env`: `STORE_BILLING_ENABLED=true` и остальные `APPLE_IAP_*` / `GOOGLE_PLAY_*` из `STORE_RELEASE.md`.

## 1. Что заполнить руками (в коде оставлены заглушки)

- [ ] **Реквизиты компании** и телефон поддержки в `apps/web/lib/legal-content.ts` и `apps/mobile/lib/legal/content.ts` — сейчас «Реквизиты компании уточняются» и `+7 (700) 000-00-00`. Apple и Google смотрят на страницы Privacy/Terms/Support.
- [ ] **Демо-аккаунт для ревьюера Apple**: специального ревью-входа в коде нет (OTP-бэкдор закрыт), поэтому создайте обычный аккаунт с email+паролем (`apple-review@my-test.kz`), выдайте ему активный тариф в админке и впишите логин/пароль в App Review Information («Sign-in required»). Проверьте вход этим паролем на свежем устройстве.
- [ ] **Цены в консолях**: тарифные уровни для четырёх продуктов подберите под новые цены сайта 490 / 900 / 1490 / 2990 ₸ (в приложении цена берётся из стора, а не с сайта).
- [ ] **Скриншоты**: iPhone 6.9" и 6.5", iPad 13" (у нас `supportsTablet: true`), Android phone. Снимайте на новом дизайне — старые скриншоты не подходят.

## 3. Требования сторов к UGC (сообщество) — что реализовано

Apple 1.2 и Google Play «User Generated Content» требуют всего ниже; всё уже есть в приложении:

- Фильтр недопустимого контента на сервере (посты, комментарии, сообщения, названия групп, имена) — `apps/api/src/modules/social/domain/content-filter.ts`.
- Пожаловаться на пост, комментарий, сообщение чата и профиль; заблокировать пользователя (скрывает его контент и закрывает личные сообщения).
- Правила сообщества и условия согласия при первом входе в сообщество; ссылка на правила в профиле и в чате.
- Очередь модерации в админке, удаление контента и блокировка автора.
- Контакт поддержки: `support@my-test.kz`.
- Удаление аккаунта внутри приложения: Профиль → «Удалить аккаунт» (Apple 5.1.1(v)).

В **App Review notes** напишите: `Community: More → Community. Reporting: ⋯ menu on any post / message → Report. Blocking: user profile → ⋯ → Block. Moderation: reports reach our admin panel and are handled within 24 hours.`

## 4. Разрешения и приватность

| Разрешение | Зачем | Когда запрашивается |
| --- | --- | --- |
| Фото (галерея) | аватар и картинки в чат | только при выборе файла |
| Микрофон | голосовые сообщения в чате | только после нажатия на запись |
| Камера, геолокация, контакты, трекинг | **не используются** | — |

Тексты запросов двуязычные (RU/EN), прописаны в `app.json`. Приложение больше не запрашивает геолокацию.

### App Store Connect → App Privacy
Собираются и связаны с пользователем: контактные данные (телефон / email), имя, идентификатор пользователя, **пользовательский контент** (посты, сообщения, фото профиля, голосовые), результаты тестов (другие данные об использовании), покупки. Трекинга нет. Google Sign-In на iOS не показывается (Apple 4.8), вход — телефон/email.

### Google Play → Data safety
Те же категории: личная информация (имя, email, телефон, ID пользователя), сообщения и аудио (голосовые сообщения), фото, активность в приложении, финансовая информация (покупки через Google Play). Данные передаются по HTTPS, удаление — в приложении (Профиль → Удалить аккаунт) и по запросу на support@my-test.kz. Опубликуйте URL правил удаления данных: `https://my-test.kz/support`.

В разделе **Контент приложения** отметьте: приложение содержит пользовательский контент → да, есть фильтрация, жалобы и блокировка; рекламы нет; целевая аудитория 13+ (для UGC-раздела) — согласуйте с юристом, если хотите ниже.

## 6. Сборка и отправка

```bash
cd apps/mobile
npm run release:check          # контракт релиза + tsc
npx expo-doctor                # проверка зависимостей (опционально)
npx eas-cli build --platform all --profile production
npx eas-cli submit --platform ios --latest
npx eas-cli submit --platform android --latest
```

`buildNumber` / `versionCode` наращивает EAS (`appVersionSource: remote`, `autoIncrement`). Для Android первый выпуск отправляйте в internal/closed testing и проверьте чат, голосовые и покупки лицензионным тестером до production.

## 7. Что не было проверено на устройствах

Честный список для тестового прогона перед отправкой:

- Android: пройден эмуляторный прогон входа, дашборда, ленты, чатов, клавиатуры. **Не проверялись** на устройстве: экзамен (пауза, апелляции), разбор, ошибки по темам, настройки группы, голосовые/вложения, покупки.
- iOS: запуск не проверялся (нет Xcode на машине сборки), только компиляция бандла. Обязательно пройдите TestFlight-билд по сценариям выше.
- Графики AI-коуча на телефоне упрощены относительно веба; экраны «Поступление» и «Тарифы» не сверялись с вебом построчно.
